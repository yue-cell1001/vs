# 模块化公交固定—DRT 两阶段双目标优化

本版本以 `main_program_settings.docx` 为主程序设定，`Draft.docx` 为机制说明，
运行时使用本地 `Test.zip` 的全部原始 CSV；按用户要求，GitHub只保存代码，不上传该数据集。文档中参考满载率 0.8 与公式 0.9 的冲突，
已按用户确认统一为 **0.8**。不沿用旧包的容量 8、编组 7、货币化时间目标或 16 动作学习器。

按用户后续确认，**初始化和修复内部逻辑保持上传原版**，不使用此前替换的 first-feasible 构造。
初始化、构造式修复、插入修复及恢复支援四个源码文件与上传版本逐字节一致。

## 安装与运行

先将你本地 `Test.zip` 中 `Test/` 下的 CSV 文件复制到项目根目录的 `data/` 文件夹。
数据目录和历史方案已加入 Git 忽略规则；不要把数据提交到 GitHub。

推荐 Python 3.12，在项目根目录执行：

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python run.py --output results/main
```

默认第一阶段种群 100、300 代，最多输出 15 套代表时刻表；第二阶段每套最多 200 次迭代，
保留原版连续 60 次未保留新解的停止条件，以及默认 3 组初始化规则。
主程序设置文档未另行指定搜索规模，因此保留上传代码的种群、代数和第二阶段迭代默认值。
整数子问题默认不限时；可显式设置 `--subproblem-seconds 30`，其限制的是每次整数求解，
不是整个时刻表或整个程序的总耗时。限时可行解会记录 gap 和“未证明最优”状态。

分阶段运行：

```bash
python -m stage1.main --output results/main/stage1.json
python -m stage2.main --timetables results/main/stage1.json --output results/main/stage2
```

只跳过第二阶段 Excel 和图片、保留全部 JSON 与逐轮候选：

```bash
python run.py --output results/json_only --no-reports
```

仅关闭第二阶段绘图可用 `--no-plot`。小预算开发验证可显式指定参数，
例如 `--population 4 --generations 1 --evaluation-budget 12 --iterations 1 --subproblem-seconds 30`；
小预算验证不等于完成默认规模优化，也不保证所有输入时刻表都能构造出可行解。

## 采用的设定

- 给定需求：3000 名普通乘客、300 名 DRT 乘客；不重新生成、删减或重采样。
- 8 个方向、85 个固定站点（含 8 个换乘站）、8 个同址仓库、600 个 DRT 端点。
- 始发基准 08:00—10:00，间隔 5—15 分钟；允许末班及乘客服务在 10:00 后完成。
- 每模块 6 人，每个固定班次每段 1—4 个模块；参考满载率 0.8 不替代硬容量约束。
- 每仓库初始 5 个备用模块、库存上限 20 个；未启用的备用模块不收费。
- 普通乘客不换模块、不跨线，可等待后续班次，额外乘车不超过 15 分钟。
- DRT 在给定 30 分钟接客窗内上车，最多真实耦合换乘一次，不另加统一最晚送达时刻。
- 固定路线和空驶使用有向路网；DRT 使用坐标直线距离与 30 km/h。
- 实际停站 20 秒，发生解耦/耦合时才增加相应 30 秒作业时间。
- DRT 返站耦合等待上限 10 分钟；空模块存库等待独立建模。
- DRT 后可返后续车次、继续接单、回库或沿原方向独立续行；空驶和实体模块复用均计费。

两个目标均最小化：

```text
F1 = 50 × 实际启用实体模块数
   + Σ固定编组路段 0.3 × 距离km × [1 + 0.8 × (模块数 − 1)]
   + 0.3 × (DRT模块里程 + 独立续行模块里程 + 全部空驶模块里程)
F2 = 普通乘客等待分钟 + DRT乘客等待分钟 + 普通乘客额外乘车分钟
```

额外乘车时间包括相对同线路同方向直接乘车增加的绕行、等待与作业延误。
F2 不乘时间价值，不对绕行额外打 0.5 折。

## 搜索与学习

第一阶段使用实际路段剩余容量分配普通乘客、构造参考车队与模块复用链。
输出前用第二阶段普通乘客模型验证；该验证不保证加入 DRT 后必然可行。
代表解从已评价可行解的非支配前沿中按迭代拥挤距离筛选，保留两端，最多 15 套，不补数。

第二阶段外层采用五类移除（随机、相关、边际、整链、时刻关联）和三个修复调用槽位，
前四类移除分别配三个槽位，时刻关联只配同步槽位，共 13 个动作。
**三个槽位内部仍调用原版的成本优先、乘客时间优先和局部帕累托修复**；
同步时刻调整在外层完成，不重写原修复函数为“紧急优先”等新算法。
原有协同插入、构造失败后的规则重试和支援策略继续保留。
这是用户确认的兼容选择，不能称为完整实现文档中三类修复的内部行为。

原初始化默认依次尝试 0、1、2 三组规则；不会改为遇到第一个可行解就停止。
可显式使用原有参数 `--initial-feasible-target 1` 提前达到目标，
或选择 `--initialization insertion`、`--repair-mode exhaustive`；默认均为 `constructive`。
原函数读取的几何评分参数通过兼容属性对齐新口径：跟随比例为0.8、时间按分钟计，
这些属性不恢复旧的货币化目标。原有候选枚举、选取、插入与重试顺序保持不变。

学习器只维护 **一组 13 维概率**，初始均为 1/13；学习率 0.1，固定探索比例 0.05。
可用动作集合内采样概率为 `(1−0.05) p_a / sum(p_available) + 0.05 / |available|`。
新解提升全局已探索前沿 HV 时奖励 1；否则支配原解时奖励 0.3；其余奖励 0。
更新为 `(1−0.1R)p + 0.1R·one_hot(action)`；零奖励不改变已存储概率。
HV 参考点余量 0.1，非支配档案不按固定容量截断。

## 输出与恢复

- 第一阶段：时刻表、参考评价、参数、评估/进化记录和收敛 CSV，不自动绘图。
- 第二阶段：完整方案 JSON、逐轮可行候选、失败记录、计算时间、每套时刻表汇总 Excel。
- 所有时刻表的搜索结束后，每个成功时刻表选一个最终方案，生成一套8张方向图。
  迭代中不绘图；不额外自动绘制库存图、前沿图或收敛图。前沿和收敛数值仍保存CSV。
- `checkpoint.json` 同时保存随机数、统一学习器及搜索档案；`finished.json` 标记完成的时刻表。

相同输入及参数下续跑：

```bash
python run.py --output results/main --resume
```

之前已记录初始化失败的分支需重试时加 `--retry-failed`。
旧模型的断点、方案和 `docs/legacy/` 中的历史时刻表不兼容，请使用新输出目录。
`model_version`、参数及全部 CSV 指纹用于防止跨模型或跨数据续跑。
本次回退使用 `main-settings-original-init-v2`，不可与此前替换过初始化的版本混用断点。

计时分别记录 `initialization_elapsed_seconds`、`iteration_elapsed_seconds` 和每轮 trace，
外层 `timing.json` 另记最终 Excel/绘图的 `report_export_seconds`。
此前156.7秒是回退前版本的完整代表运行，不是单轮耗时，不能当作本版耗时。

独立检查保存结果：

```bash
python -m stage2.verify_run results/main/stage2
python -m unittest discover -v
```

计算的帕累托前沿是已探索可行方案的经验前沿，不是全局最优性证明。
文档到实现的对应关系见 [修改说明](docs/changes.md)。
纯代码检出不包含私有数据校验清单，数据集回归会明确跳过；正式计算需要先准备本地数据。
